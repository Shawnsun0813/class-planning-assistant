# 用户问题与价值假设

同学需要在个人目标、上课时间、课程要求和竞价预算之间做取舍。本产品拟将这些条件与课程内容、历史记录和评价放在同一次决策中，减少手动筛选、拼课表和重复核对的负担。

价值假设是：本人及其他同学能够更快形成满足约束的选课方案，理解推荐原因及竞价风险，并愿意用于实际选课。先由本人用真实任务检验，再检查其他同学的条件差异；与原有做法比较，不把真实对话或本人单次使用当作效果及普适性证明。

职业相关性指课程内容与用户目标的关联，不等同于就业机会或求职结果保证。

# 首位用户与方案决定

本人是首位用户，以本人的真实选课任务先验证完整路径，再验证其他同学的差异。个人职业背景、时间和选课偏好不作为所有同学默认条件。

导入对话中，历史助手展示过标称22学分方案，并建议删除554形成18学分分支，或保留554、用Pricing替换561形成20学分分支。该片段未见用户采纳，三者不能自动合并或认定为最新确认版。对话中的学分与课时也尚未用正式资料验证。

区分三类方案：历史导入基线、待采纳讨论方案、用户已确认方案。探索性问题不自动切换方案；明确采纳才更新。请求最新课表时，有确认记录则展示最近确认版本，否则说明当前仅有导入基线及未决选项。

恢复上下文时同时标明来源和生效状态：用户直接确认、历史转述、助手建议、待核实。个人条件可批量核对；官方事实存在冲突或缺失时，指出受影响的结论，不强迫用户重填全部信息。

[首位用户案例与验收场景](FIRST-USER-CASE.md)保存原始课表、候选课程、条件分支及C01至C12案例。PRD定义通用行为；案例文档不另行维护一份已确认最新课表。

# 首版范围建议

首版聚焦一个 SOM 学位项目、一个学期及明确竞价阶段，先围绕本人已有选课任务完成恢复、比较、修改和预算建议的完整路径，再供其他同学验证。全学期、S1和S2需要共同支持；多学期规划不在首版范围。

首版应包含：

- 从已有对话恢复历史方案、硬约束和偏好，批量核对缺口，避免从零重填。

- 课程和教学班信息浏览，以及推荐原因和资料来源。

- 优先提供一套完整可行课表；可额外展示至多三套方案，方案数量不是验收条件。

- 在当前选课任务中讨论、锁定、排除和替换课程；区分待采纳分支与已确认方案，展示修改差异。

- 针对所选课表的竞价分数建议、总预算分配及落选后的备选课程。

首版暂不包含：代登录、自动报名或提交出价、自动执行多轮竞价、完整毕业资格审计、跨校通用规则引擎、社交评价社区和收费系统。公开发布或向同学发送邀请需遵循届时的具体授权。

课程推荐、排课和竞价建议共同构成目标。必要数据不足时可分阶段验证，但不得把只有静态课表或模拟数据的版本当作完整首版。

# 首版使用路径

1. **恢复与核对。** 确认项目、学期及竞价阶段；有历史对话时先恢复方案、条件和未决分支，注明来源与确认状态，仅核对缺口。没有已确认方案时，显示历史导入基线，不能称为最新确认版。

2. **确认个人条件。** 补充不可用时间、必选或已选课程、学分范围、已知资格、求职或学习方向、其他偏好、可用预算与风险偏好。计算前展示采用的条件；硬约束、偏好及限定学段或课程的例外分别处理，历史助手转述不自动生效。

3. **比较课程与课表。** 在全学期、S1和S2范围查看方案，比较新增学习价值、已有课程或实践重叠、作业形式、课堂时间和未知课外负担；区分证据、传闻与推断。retreat、小组及其他已知活动一并检查。

4. **讨论并采纳修改。** 探索性问题只产生解释或待采纳方案，不改变当前方案。用户明确采纳后，展示并应用增删课程、学分、分学段时间、冲突、预算及未核实项的差异，保留其他有效条件；支持返回修改前方案。

5. **查看竞价建议。** 展示所选课表各门课程的建议分数、预算合计、参考记录、主要风险及可用备选。

6. **自行提交。** 用户核对方案后，在学校适用系统内自行完成选课或竞价。本产品的建议不代表实际报名或中标。

| F02 | 基于个人条件推荐课程 | 解释新增学习价值、与已有课程和实践的重叠、作业形式与投入；区分证据和推断，不只按课名或评分推荐 |

| F06 | 支持修改和重算 | 采纳锁定、排除和替换后保留其他条件，展示前后差异，重查课表、学分和预算；可回到修改前方案 |
| F07 | 分配整套竞价预算 | 规则和数据依据支持时，输出可操作的建议值或区间及整套分配；最终采用值合法且总额不超预算 |

| F12 | 恢复已有上下文 | 导入历史基线、分支和条件，注明来源与确认状态；只补缺口，不要求从零重填 |
| F13 | 区分讨论与决定 | 询问课程是否值得上或转述评价，不自动删课；只有明确采纳才更新方案 |
| F14 | 查询最新课表 | 优先展示最近确认方案及其范围；没有确认记录则明确展示历史基线和未决分支 |
| F15 | 管理限定例外 | 仅按用户明确接受的课程、学段或日期放宽指定条件，不能全局放宽 |

| F17 | 显示影响与未知 | 分别说明课堂、总跨度和课外负担；不把无常规课当完全空闲，不将约略时间写成精确值 |

# 数据与竞价依赖

| 数据类别 | 最少需要确认的内容 | 不足时的处理 |
| --- | --- | --- |
| 当期课程资料 | 课程与教学班标识、学期、内容、学分、日期和时间、适用资格及关联班级 | 缺少关键时间或资格时不能宣称方案已验证可选 |
| 选课和竞价规则 | 参与条件、可用预算、轮次、分数单位与范围、分配及平分机制、撤改和退分规则 | 未确认适用规则前，不计算可执行的出价分配 |
| 历史 bidding | 记录对应的课程、教学班、学期、轮次，以及字段表示个人出价、成败结果还是最终门槛 | 不混用含义不同的记录；仅有门槛时展示历史参考，不能据此推导成功概率 |
| 课程评价 | 对应课程、教师和学期、评价维度、样本量，以及可供同学使用的范围 | 缺失、样本有限或时效性问题可见，不编造工作量或评分 |

已接入的4份Excel按下文的实际资料记录处理；首位用户选课对话仅作需求与来源处理案例。新增评价数据仍须核对字段、课程身份、规则可比性和供同学使用的范围，去除无关身份信息。校内查看权限不自动等于允许公开再分发；用户私人导入资料不得随静态部署发布。来源与决定状态分开记录：用户采纳方案不代表课程事实已获官方核实。

竞价建议先核实历史记录含义，以及与当前规则、课程和教学班的可比性。证据支持时提供建议值或区间，说明适用轮次、总预算和已占用分数、依据、假设和不确定性；区间须配合一套不超预算的可操作分配。历史门槛不等于预测值，证据不足时该能力受阻，不能用任意分数补齐。只有在数据和验证支持时，才考虑给出成功概率。即使如此，也不保证中标或精确预测最低中标分数。

多人采用相似建议可能改变竞价需求，历史回测效果不能直接等同于未来多人使用效果。

# 验收条件

以下为首版验收要求；各项实际检查范围与未完成依赖见TASK.md及独立评审，不因部分检查通过而整体标为完成。

| 编号 | 检查内容 | 通过条件 |
| --- | --- | --- |
| A01 | 完整使用路径 | 使用真实当期课程与适用规则，从个人输入完成课程推荐、课表和整套竞价建议 |
| A02 | 硬约束 | 输入被正确转为用户确认的条件；所有可行方案满足已明确且有数据可核验的硬约束，关键未知仅为待确认候选 |
| A03 | 无解处理 | 时间冲突、必选课冲突、资格受限或预算不足时给出明确原因，不输出违规方案充当成功 |
| A04 | 修改后有效性 | 锁定、排除、替换课程后，保留有效输入并重新检查受影响条件 |
| A05 | 竞价合法性 | 建议值符合已确认分数规则，合计不超过当前可用预算；备选切换同样重新检查 |
| A06 | 依据与缺失 | 推荐和竞价依据可追溯；关键规则或数据缺失时停止对应估计，不伪造记录、概率或评价 |
| A07 | 多人使用 | 两位同学分别操作时，个人条件、课表及私人数据不会串用或互相暴露 |
| A08 | 实际可操作性 | 在真实运行入口完成核心操作，并检查窄屏、长文本、空状态、错误恢复和关键键盘操作 |
| A09 | 竞价效果验证 | 数据足够时，使用未参与调整的历史批次，与简单历史参考方法比较；说明指标、样本及局限，不能仅以能输出数字验收 |
| A10 | 用户价值验证 | 先由本人独立完成恢复／输入、比较、明确采纳修改及查看预算，再检查其他同学的条件差异；与原有做法比较 |
| A11 | 讨论不改方案 | 询问554是否必选、转述PM很水时，仅生成解释和待采纳分支，当前课程与预算不变 |
| A12 | 方案状态与差异 | 正确区分22学分历史基线及18／20分支，未采纳不合并；有确认记录才称最新确认方案 |
| A13 | 半学期和特殊活动 | 按学段核对冲突；retreat日期未知时只说明常规课程检查范围，不声称整学期无冲突 |
| A14 | 例外范围 | 为某课放宽S1某日条件时，仅该明确例外生效，其他条件保留 |
| A15 | 证据与新课 | 传闻不变事实，未知时间不编排为可行；新课缺评价不自动排除 |
| A16 | 变更恢复 | 应用修改后可回到修改前方案；来源变更或冲突显式提示并重查受影响结果，不静默改写用户决定 |
| A17 | 简介全链路 | 对当期全部官方记录逐条比较归一化简介；有简介不丢失、真缺失不填造，含HTML、实体和Q&A等边界有回归检查。桌面和手机可读摘录及全文 |
| A18 | 评价真实接入 | 逐来源检查实际HTTP／认证结果与SOM覆盖范围，页面显示覆盖和局限；公开体验、访谈与助教背景分开。无权限的校内评价保留依赖，不因存在入口链接而标为数据接通 |

A09 的样本范围、时间切分、比较基准、可观察结果、指标及通过标准应在看结果前确定。不得使用历史决策当时不可得的信息，或从仅有中标记录推断未观察到的失败情况。数据不足时列明缺失条件，竞价效果标为未验证，不因界面可用而自动通过。A10 用于判断试用价值，工程检查通过不代表同学愿意采用。

合成场景可用于检查有解、无解、锁定后失效、预算不足、评价缺失和只有历史门槛等分支；合成课程与分数须明确标注，不能冒充 Yale 实际资料。

# 主要风险与待确认事项

最高风险仍是竞价规则与历史数据能否支持可检验建议。真实案例还暴露了方案被误改、历史助手断言被当成用户条件、半学期或特殊活动漏算的风险；这些与课程身份、当期信息及评价质量同属首版正确性范围。

| 待确认事项 | 影响 |
| --- | --- |
| 具体 SOM 学位项目及正式选课范围；核对案例所标2027春季 | 决定课程范围和规则；首位用户已确认为本人 |
| 适用选课与竞价规则 | 决定分数建议及预算计算能否成立 |
| 当期课程资料和历史数据样例 | 决定可推荐、可排课及可验证的范围 |
| 课程评价与历史记录的可用范围 | 决定哪些资料可供同学使用 |
| 从历史恢复的个人时间条件、保留课程、背景及风险偏好 | 决定职业相关性、时间便利、工作量、偏好课程和保留分数之间的取舍 |

未提供上述信息不妨碍审阅 PRD，但依赖这些信息的实现和效果承诺应保持待定。产品语言、账号方式、部署位置和具体技术路线在进入相应阶段后再决定，不先扩建平台。

# 开始后的推进与交付

用户已明确要求开始，按以下阶段推进：

1. 主 Agent 核对项目、规则和数据样例，更新范围与必要验收，优先验证竞价建议所依赖的数据条件。

2. 设计者围绕真实内容和核心使用任务完成一个可检查的核心页面及必要交互状态。

# 本轮新增实施约束

- 网站入口：https://courseauction.som.yale.edu/courseauctionfrontend 。只访问可用且获准的数据，登录或网络阻塞如实记录，不绕过访问控制。
- 用户提供Auction-Bidding-History.xlsx、Enrollment-History.xls、International-Exchange-Bidding-History.xlsx及SOM Students in NonSOM Courses for Portal.xlsx。先检查字段和共享范围，普通课程、国际交换及跨院规则不混用。
- 网上搜索课程评价；区分公开一手体验、官方描述与受登录限制的评价。找不到时保留缺失。
- 模型必须免费，不创建或调用付费API。优先验证无需密钥的本地开源推理；模型不可用时不得把规则解释标为大模型输出。核心排课与预算约束不依赖模型自行保证。
- 支持不同同学分别使用，个人方案不串用。试用预览不等于长期托管；多人长期使用需要适当部署，正式发布保持待授权。

- 首版多用户方式为各浏览器本地保存，可用命名方案分别验证；同一浏览器的本地场景不是安全账号边界，不声称云端鉴权或跨设备同步。

# UI 与交互改版要求

2026年11月11日用户反馈界面过于模板化，要求更有设计感、酷一些，并要求多Agent分析与更新。产品目标与业务约束不变，本轮调整呈现与操作层次。

采用经设计与独立批判后的学术课程目录方向：墨黑紧凑导航、纸白工作面、清晰字阶、整行课程索引及克制状态用色。取消营销口号和重复圆角卡片，首屏直接进入课程任务。手机默认展示条件摘要与编辑入口，结果渐进展开，课程比较与可选本地AI入口保持可达。来源、资格未知、讨论分支、确认状态和预算错误不得因视觉简化而被隐藏。

本轮验收包括实际1440桌面与390手机效果、长课程名、默认搜索触达，以及原讨论采纳撤回、预算与数据恢复路径不退化。具体设计和视觉取值见DESIGN.md；不改变核心排课、竞价与本地存储语义。
