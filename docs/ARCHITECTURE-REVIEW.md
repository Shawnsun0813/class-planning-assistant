# 全栈建设建议与当前项目取舍

日期：2026年11月11日（America/New_York）。用户已明确该清单是产品建设建议，不是课程作业硬性要求。两位子Agent分别从产品阶段和技术依赖独立评估，主Agent综合；本轮仅评估，未启动重构、建库、账号或OpenRouter接入。

## 结论

不必把清单整套设为当前上线门槛。现版可作为公开试用工具，供同学在各自浏览器使用。若目标是长期登录使用、跨设备继续、找回方案和统一AI服务，建议下一阶段补精简全栈：成熟框架、标准鉴权、用户所属数据库记录、服务端模型接口及恢复测试。保留已有界面、排课规则核心和可重现数据处理，不整站重写。

当前localStorage确实持久保存于单一浏览器，但没有账号归属、跨设备恢复或服务端数据权限；清理浏览器或共用设备的边界仍在。当前免费浏览器模型未跑通是真实缺口，不能把代码接入等同于稳定可用AI。

## 逐项评估

| 建议 | 当前取舍 | 需要时的最小要求 |
| --- | --- | --- |
| 成熟全栈框架 | 当前静态试用不必迁移；决定加服务端能力后采用一个成熟框架 | 复用界面与规则核心，集中处理路由、鉴权、数据访问和测试，不继续散拼后台 |
| 数据库与标准账号 | 长期登录、跨设备保存或私人资料归属成为目标时必要 | 用户所属方案记录、服务端授权、双用户隔离／越权测试、备份及恢复 |
| 服务端调用OpenRouter | 共享云端模型需要服务端密钥及权限控制；OpenRouter不是唯一选择 | 认证、每用户限流、超时／错误、模型白名单、费用与数据发送边界；禁止付费回退 |

## 两个应反驳的极端

“给同学用就必须先补齐全部设施”会在未经确认的实验和管理功能上增加成本，且不能替代课程身份、竞价规则与推荐价值的核实。

“静态页面能打开就已完成多人产品”同样不准确。现版缺少账号云数据和稳定统一模型服务；一旦这些成为承诺，应补齐并验证，不能靠命名本地方案冒充。

## 免费模型与部署边界

OpenRouter官方当前免费限制为每分钟20次、免费账户每日50次；官方说明累计购入至少10美元额度后免费模型日限额可提高至1000。它不能被视作无限量多人服务，也不能保证后续型号与政策永远不变。用户的免费约束仍有效，不因评估而充值、创建密钥或允许付费回退。

来源：[OpenRouter价格与限额](https://openrouter.ai/pricing)、[限额说明](https://openrouter.ai/docs/api_reference/limits)。

GitHub Pages只托管静态应用，不能承载服务端密钥、鉴权与数据库后端。若采用统一云模型及账号，需要另有合适的服务端运行环境；当前成功Pages部署可继续作为试用入口。来源：[GitHub Pages说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。

## 建议顺序

1. 使用当前已部署试用版验证本人和少量同学的实际选课路径。
2. 明确是否承诺登录、跨设备保存和稳定AI；若承诺，下一里程碑优先标准账号＋数据库＋服务端模型接口，配迁移、seed、备份和环境隔离。
3. 核心留存与推荐有真实证据后，再按具体问题增加实验、统计和管理工具。

以上是建议，不自动改变PRD或授权实施路线。
