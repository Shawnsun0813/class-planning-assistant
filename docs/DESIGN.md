# Yale SOM 选课助手界面设计

版本：0.2｜2026年11月11日（America/New_York）｜任务：DESIGN-02。

本版替代0.1视觉方向。用户要求界面更有设计感、更酷，减少“AI味”。业务目标、课程资料与正确性要求继续按PRD执行，不重新立项。设计者已用独立Chromium实际查看1440×1000课程探索、历史S2课表及390×844窄屏；本版定义待实施方向，尚不代表新界面已经运行验收。

## 现版问题

实际页面的主要问题是统一圆角白卡、灰蓝小字、重复图标与色签形成模板节奏。营销句、学期徽章和方案卡在真正选课操作前占据较多高度。课程采用两列同形卡片，每条重复推荐说明、状态与按钮，难以快速比较。同一条未核事项在多个淡黄色区域重复出现。手机将整套条件栏排在工作区之前，进入课表任务前须滚动较长距离。

这些是当前设计的可检查差异，不是对所有卡片、浅色或图标的普遍禁令。本轮改变信息节奏、任务入口与文字层级，不以换主题色代替重做。

## 两种方向与选择

| 方向 | 具体表达 | 适用与代价 |
| --- | --- | --- |
| A Course Index 学术目录 | 墨黑紧凑顶栏、暖纸色工作面、衬线课程标题、等宽编号、细分隔线、整行目录；钴蓝只用于主要操作 | 适合长课程名、资料阅读、方案比较；通过字体和结构产生个性，保留白天使用清晰度 |
| B Night Desk 研究终端 | 全深石墨界面、银灰排版、等宽数字与紧凑行、少量冷蓝交互、低亮度周历 | 夜间有辨识度，但长段评价阅读、未知与危险状态的对比和色彩区分成本更高；容易退化成泛科技终端 |

采用A。它让产品接近一份能操作的大学课程目录和个人选课记录，表达克制、精确和判断力。酷感来自强字阶、留白比例、行列秩序和操作反馈。B暂不制作双主题，避免范围扩展。

## 页面骨架

桌面1440下，页面不再由一个营销hero和一列列浮起卡片组成。使用约72px紧凑深色页头、约65px方案状态带、约260px条件工具区与其余主工作区。页面内容边距28至36px，工作区列间24至32px。保留现有单页和同一份个人状态，不引入新路由或平行组件系统。

### 页头与当前方案

左侧字标可用“SOM / PLAN”，不使用虚构校徽和现有带箭头的图标块；完整产品名保留在页面标题或副标题，注明独立选课辅助身份。右侧用文字链接处理导入、导出和资料，避免三个主按钮争夺注意。

2027／SPRING作为真实学期索引放在页头或工作区标头，来源快照日期在资料处可查。删除“为值得上的课，留出时间”等宣传句和额外学期徽章；主标题直接说明正在执行的任务。

方案栏以横向记录带呈现，使用细分隔线：方案名称选择器、历史导入／讨论方案／已确认状态、总学分、课程数、待核数。数字用大号等宽或tabular-nums，标签用清楚中文。状态用文字和少量符号，不靠一排彩色药丸；未知不能被藏到只剩颜色。

### 工作区导航

保留“课程探索”“课表与方案”“竞价建议”三个可访问名称和状态，不改变原测试与用户心智。可视觉加01／02／03序号，但序号不替代中文任务名。导航为文字与细底线；当前项用墨色粗字、钴蓝线或小矩形，避免发光、渐变与大图标。

工作区标题采用有明确任务含义的英文衬线字，例如Course index、My timetable、Bid ledger，同时保留中文说明。桌面标题30至36px，行高1.05至1.15；它是当前面板的紧凑标头，不另增一段封面、装饰编号或高hero。手机缩至26至30px。

### 条件工具区

条件栏去掉外层大圆角卡片和分组卡套卡，改为细横线分段的工具区。保留职业／学习方向、学分、不可用时段、例外、小组和retreat、确认条件与生成入口。默认展开主要输入，其余用已有details展开，不新建复杂抽屉。

“确认这些条件”和“生成候选课表”职责保持分别清楚；生成是该区唯一实色主操作。历史案例恢复、18／20分支和新同学方案放在次级分段，以简短文本操作呈现。已存在方案再次导入仍遵守保护原方案的逻辑。

## 课程目录

桌面默认整行目录，替代两列等高课程卡墙。建议行内结构为：课程号与section约100px、标题及教师为弹性主列、学段／学分／时间作为右侧资料、操作区位于行尾或标题下的明确次行。约100至140px行高由真实内容决定，不固定截断长课名；长标题最多自然占所需行数。

课程标题用衬线20至24px，教师与时段用无衬线13px，课程号用等宽12px。区分“Teaching section”“S1/S2”“学分”无需每项配装饰性图标。已加入讨论的行以左侧2至3px墨色或钴蓝标记和“已在方案”文字指示，不依赖阴影。

每行保留比较、加入／移除讨论、锁定与排除的功能和可访问名称。加入讨论是明确动作，不命名为已经报名。展开课程依据时，用排版和细左线区分官方内容、个人体验及局限；不要用一组背景卡复刻整条目录。

推荐解释只在有实际匹配时简洁显示；未发现关联不需要在155行重复同一长句。相关性排序解释可以在结果标头写一次，逐课依据仍可展开。没有评价与资格未知必须可见，但采用小字文本或行内标记，避免所有课程都占一块黄色提醒。

搜索和筛选成为一条紧凑工具行，结果数与排序说明在其下以小字标注。搜索框保留清楚焦点，不用装饰性键盘提示。默认显示20至24条，提供“查看更多”并显示已显示／总结果数；筛选或搜索改变时重置该数量，不更改结果语义。比较和课程讨论应有按需入口，不能埋在155条课程后；不为本轮建立复杂数据表框架。

## 课表与方案

S1／S2切换改为明确的文字分段控制，活动项墨底纸白字，未选项可读。全学期课程同时展示，课程身份跨学段一致。周历使用白纸、细网格、深文字和少量低饱和底色；避免每个课程块都像彩色圆角徽章。现有视图按日排序而非按比例定位，必须保留这种日程列表语义，不能增添没有真实比例关系的时间轴。

星期标题为等宽小字；时间、课程号与标题分层。长标题可自然换行，课程块可点击查看完整资料。不能靠颜色判断冲突或课程；已发现冲突仍有红色文字说明。无课程的日子仅标“无已知常规课程”。

22学分是总学分，不把S1／S2涉及学分相加或伪造成官方拆分。数字和状态要在看课表时可见。小组、retreat、假期及未知日期依旧进入待核清单。

待采纳修改区采用清楚的上下分隔和新增／移除两列，突出课程及总学分变化，减少整块浅蓝背景。采纳按钮是实色主操作，放弃和撤回为文字或描边。冲突禁采纳、未知资格提示、未知课程引用保护、预算失效重算等行为不得变更。

## 竞价与状态

竞价面板采用账页式结构：总预算、已占用、当前分配、剩余为一条对齐数字记录；逐课历史依据与输入按行组织。金额／分数右对齐，使用tabular-nums。未验证规则保持一条简短明显的说明，详细边界可展开，但实际超预算与禁保存原因保持可见。

“落选退分”为用户提供规则，总分由用户自己输入；不因视觉简化而把它们标成官方认证。不合口径历史、无同名历史、空值／零值、假设草案、未知单课上限等语义保持原样。

反馈、未知与错误用不同层级：一般成功反馈为细边线加文字；未知事项为编号清单／小型摘要；实际冲突与超预算为朱红文字及边线。不能为显得干净而取消约束、来源、模型失败或恢复原文的入口。

免费本地AI解释作为辅助工具，与课表主任务分开；不使用星光图标、大面积紫色、聊天气泡或“AI赋能”标题。用“课程讨论”或“基于资料解释”等任务语言，并明确本地模型、主动下载与当前未验证运行状态。不得改变真实调用或失败处理。

## 手机与键盘

390px手机先看紧凑页头、当前方案摘要、任务导航与工作区；条件区默认折叠为“我的条件／待确认N项”，用户可展开编辑。不是把长侧栏完整放在课程前方。历史案例和新方案入口仍须在展开条件或方案摘要附近可达，不藏入未知汉堡菜单。

课程行在窄屏转为纵向资料记录，保留编号、标题、时间与主要操作；不强压桌面多列。周历继续按日列表，S1／S2切换保持可见。所有表单有可见标签，触控操作至少约40px，字号至少14px，输入字号宜16px避免移动端缩放。

条件折叠摘要显示已确认／待核状态与条件条数，提供明显的编辑文字或按钮；收起后仍能重新编辑，不只剩一个小三角。未知数、冲突数与当前方案状态不能因手机布局消失。无整页横向溢出；必要代码和来源链接可折行。折叠与标签页使用原生可访问控件或完整aria状态，焦点不能跳失。

## 实施与验收边界

本轮实施者只调整App结构、CSS和必要交互组织，沿用现有类型、课程数据、求解、预算和恢复核心。不得借换皮删除功能或改验收门槛。无需新主题引擎、付费字体、图标库或动画框架。

必须实际运行并查看桌面1440和手机390：课程探索、真实长标题MGT878、S1／S2课表、22→18分支差异、条件折叠、超预算、空搜索、模型失败和恢复原文。需操作一次比较、采纳、撤回；样式改后重跑相关浏览器回归。新截图与构建对应同一候选，旧截图只作为旧版记录，不能冒充本轮效果。

首屏指标：在1440×1000新用户课程探索中，首条课程顶部目标y不超过450px；390×844手机条件默认收起时，首条课程顶部目标y不超过700px。以实际DOM和截图测量为准，不能用隐藏关键资料达标。

完成标准：首屏直接进入任务、目录可扫视、字体与网格有明显新方向、手机不再先滚完全部条件，且来源状态和业务回归成立。主Agent和设计者的视觉判断不代表用户已经认可审美，最终仍待本人体验反馈。
